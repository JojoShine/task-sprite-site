# Task Sprite 计时、授权装扮与公开发布方案

状态：用户已确认并明确要求直接实施（2026-11-15）。执行计划见../superpowers/plans/2026-11-15-v020-release.md。

## 已确认的目标

- 北京时间每天仅累计08:30–12:00、14:00–18:00内的有效任务时间，每天最多450分钟（7.5小时）。
- 已有装扮变为可用；新增角色、皮肤具有待机、工作、休息、提醒、完成庆祝、互动六类动作，扩展内容仅对已激活有效授权的用户开放。
- 桌宠、官网、小程序与服务端源码全部公开至GitHub。
- macOS、Windows经过对应环境验证，通过GitHub Actions构建对应安装包，连接OSS建立版本、下载和回退基础。
- 官网使用https://tbtparent.me/task-sprite/，展示实际版本下载、小程序同步已实现，移除页脚运营主体、客服邮箱、域名/备案及支付相关展示；保留品牌和服务/隐私链接。
- 原任务、活动历史、授权、安装身份、工作区隔离与自动同步继续保留。

## 方案选择

推荐沿用现有三个项目、建立三个独立仓库：JojoShine/task-sprite、JojoShine/task-sprite-site、JojoShine/task-sprite-wechat；最后一个仓库仍包含小程序、API及共享契约。若同名仓库已存在，先核对所有权与内容，不覆盖。

另外两种选择是合成一个大仓库，或者把小程序和API再拆为独立仓库。前者需要迁移现有桌宠历史与工具路径，后者增加共享契约和发布协调成本，本轮均不采用。

发布先采用带版本号的OSS路径、机器可读版本清单和GitHub Releases。无需为了基础版本管理启用整个现有OSS桶的版本功能，也无需引入静默安装/强制更新。

## 计时口径

从已有activityLog恢复每段开始/继续到暂停/完成的实际活动区间，再求区间与每天两段计时窗口的交集。无activityLog的旧任务继续按已有开始/完成时间兼容。保留第一开始时间和原始秒级时间戳，不改写历史。

先累计全部有效时长，再向下取整到分钟，避免多段不足一分钟的活动逐段取整造成误差；不足一分钟显示0分钟。时长仅显示小时、分钟，不显示秒。桌宠任务面板/详情/导出与小程序列表/详情/统计/汇报采用同一口径。导出用时改为分钟及小时分钟格式，原始活动记录仍完整保留。

默认每天都按上述窗口计算；用户没有要求排除周末或节假日，因此不额外引入工作日日历。固定北京时间可避免两台电脑时区不同产生不同统计。

关键验收：全天08:00–18:30计450分钟；11:50–14:10计20分钟；18:00到次日08:30计0；跨天累加正确；暂停区间不计；多段秒数先合计后取整；旧任务和时钟回拨兼容。

## 授权装扮与动作

保留四位基础伙伴免费可用。实现当前六项预览：赤狐、团子熊猫，以及薄荷幽灵、落日机器人、霜雪柴犬、奶油橘猫。选择结果在本机持久化，并在桌宠、任务页预览和衣橱中保持一致。新增角色沿用既有像素风和矢量资源，不把静态预览图片当作已完成的动作系统。

扩展装扮及新增动作在界面与原生保存入口双重检查有效授权。沿用现有本机授权摘要和到期时间，离线仍可使用已激活且未到期授权；不把开启云同步作为装扮条件，不要求每次切换联网。

授权缺失、到期或停用时，扩展内容显示锁定并提供已有激活入口，四位免费伙伴及任务功能仍可用。若之前选中了扩展装扮，保留偏好，显示对应基础外观，续期后可恢复；不因权限变化删除任务或历史。

动作由真实状态驱动：待办/空闲、正在进行、休息/暂停、提醒、完成庆祝、点击互动；遵守减少动态效果和免打扰设置。避免高频动画定时器和无任务状态的假工作展示。

## 跨平台与构建发布

Windows当前缺少授权凭据存储实现，需要接入Windows系统凭据管理，测试保存、读取、重启保留和停用清理，不保存明文令牌。补齐平台条件编译、窗口/托盘/通知及安装包设置。

macOS保留现有签名身份和受保护凭据组件，不轮换原组件的信任身份，不向公开仓库提交任何私钥。GitHub Actions负责构建和验证候选安装包；首版macOS最终签名沿用本机受保护流程，校验后再发布OSS最终包。本轮不以公开仓库为理由自动上传本机签名私钥到GitHub，也不注册可执行公开PR代码的本机runner。

初始发布版本建议v0.2.0。Actions执行前端/原生测试、构建、安装包检查和启动冒烟测试，留存日志与结果。macOS至少完成当前Apple Silicon实机验证，Intel产物有对应构建及运行环境证据才列入可下载清单；Windows在Windows运行环境验证，不能把Mac上的交叉编译当作Windows功能验收。

流程：提交触发检查；版本标签触发候选包构建；验证完整且最终包校验成功后上传OSS固定版本目录，生成版本记录，最后更新latest.json。任何目标失败则不更新公开最新版本。基础发布保留历史版本及校验和，回退通过将最新清单重新指向已验证旧版本实现。

公共仓库只发布源码、公开素材、依赖锁文件、测试和脱敏配置示例。环境文件、授权码、签名材料、数据库、真实任务截图/验收数据、备份、构建缓存均排除，并检查准备公开的Git历史。现有本机历史先保留，不进行破坏性清理或强制推送。没有新增开源许可授权的要求时，不擅自添加许可证。

## OSS与官网

沿用已配置OSS，使用独立task-sprite/releases/<version>/前缀，存放最终安装包、SHA-256、文件大小、平台架构、版本说明和版本清单。只有明确作为下载发布的安装包及清单可以公开读取，现有业务文件保持原权限，前端不接触访问密钥。

官网从/task-sprite/releases/latest.json读取最新版本和实际可用平台，下载指向对应OSS对象；某平台没有已验证产物时显示真实不可用状态，绝不生成占位下载链接。版本号、更新时间、文件大小与校验信息来自同一清单。

部署保持/task-sprite/官网和/task-sprite/api/接口路径隔离，先核对现有Web服务配置，追加该项目路径，不覆盖其他站点。当前公网/task-sprite/api/health返回404，因此公开下载宣称可用同步前，需要正式接口部署与微信合法域名配置的实际验证。安装包正式目标不能继续指向127.0.0.1。

官网同步文案改为已支持（授权码开启），移除开发中、免费同步方向等过时说明；不增加付款或领取授权码的虚假入口。没有支付时仍保留现有服务与隐私链接，页脚只保留品牌和这些链接。

## 顺序及完成标准

1. 计时改造：桌宠、小程序及导出黄金样例一致，原历史数据不变。
2. 授权装扮/动作：六项现有扩展可使用，六类动作可验证；无授权不能绕过原生入口；现有有效授权离线可用。
3. Windows补齐、macOS回归：任务增改删、开始/暂停/完成、工作时段计时、衣橱、托盘/窗口、提醒、授权和自动同步有对应平台证据，升级后原任务及授权保留。
4. 公开源码与Actions：发布内容完成脱敏检查，三个仓库可访问；真实工作流成功，不仅写出配置文件。
5. OSS/官网：产物上传后实际下载校验一致，版本清单可访问且旧版本可回退；公网官网路径、接口健康和已授权双端同步通过验收，页脚与文案更新完成。
